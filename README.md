# CS 320 Software Testing Portfolio Reflection

## How can I ensure that my code, program, or software is functional and secure?

I can make sure my code is functional and secure by testing it regularly and making sure it meets all the requirements. Throughout this course, I used JUnit testing to check that my contact, task, and appointment services worked correctly. I tested valid and invalid information to make sure the programs would accept the correct inputs and reject anything that did not meet the requirements. I also learned that just because code runs does not mean it is completely correct. Testing helps catch mistakes early, while input validation and protecting sensitive information help make software more secure.

## How do I interpret user needs and incorporate them into a program?

I interpret user needs by carefully reviewing the requirements and understanding what the program is supposed to accomplish. For example, in this course, each service had specific requirements for things like character limits, unique identification numbers, and what information could be updated or deleted. I used those requirements to determine how the code should work and what needed to be tested. I think it is important to understand what the user expects before writing code because missing even one requirement could cause problems later.

## How do I approach designing software?

When designing software, I like to break the project down into smaller parts instead of trying to complete everything at once. During this course, I worked on the contact, task, and appointment services separately and made sure each one met its requirements. I focused on writing code that was organized, easy to understand, and could be tested. I also learned the importance of checking my work throughout development instead of waiting until everything is finished. In the future, I plan to continue using this approach because it makes it easier to find mistakes, make improvements, and maintain the software.
